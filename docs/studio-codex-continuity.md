# Codex 连续会话与 Goal 绑定（0.8.1）

旧适配器每遇到一次工具调用就关闭 Codex，下一个步骤再新建临时线程并重放 DSH 历史。DSH 的历史保留文本、工具与结果，但这不等于保留 Codex 的原生推理状态。多步工作因此不断重新进入推理，工具的启动与返回也被切断。

0.8.1 为每个 DSH 会话保留独立的 Codex app-server 线程。Codex 发出动态工具调用后，适配器把调用交给 DSH，保留等待中的 RPC；DSH 执行并检查权限，再把实际结果送回该调用。后续推理在同一个 Codex turn 继续，消息和工具仍通过 DSH 原生会话流展示。图片和工具错误保留原始类型。

## 工作区、引导与恢复

- 工作目录取自该 DSH 会话的实际工作区，不使用桌面进程的启动目录。
- 中途引导沿用 DSH 的输入队列，在下一个工具结果交回模型前加入原会话。它不会强行撤销已经执行的工具，也不直接控制外部 HexaShell 进程。
- 暂停或取消关闭当前连接。恢复时只导入 DSH 已记录的历史和工具结果，不自动重试不确定的动作。
- 正常结束后保存线程编号和历史指纹。空闲一分钟释放进程，下次从持久线程恢复；桌面重启后也能恢复已经正常结束的线程。
- 工作区、模型、推理等级、工具集合变化，或 DSH 历史压缩、编辑导致指纹不再一致时，从当前 DSH 历史重建。中断的工具握手也通过历史恢复。这些路径不会保留旧 Codex 推理状态。
- 标题生成等辅助调用继续使用独立临时线程，不混入主会话。

线程记录和计时保存在 Studio 状态目录的 `codex-conversations/`，仅包含编号、指纹及计时；原生 Codex 仍管理它自己的会话存储和登录。适配器不复制认证信息。`timings.jsonl` 的 `mode` 可区分 `start`、`continue`、`resume` 和 `rebase`。

## Goal 与任务只绑定一次

自然语言调用 `create_goal`、`/goal 复现|优化|开发` 和恢复旧 Goal 都连接到同一套工作区任务记录。控制器负责建立绑定，不要求模型猜测编号。原生 Goal 编号用于 Goal 工具，任务编号用于 `refine_task` 等项目工具；共享上下文明确提供两者。已移交任务不会被旧会话的迟到事件重新抢回。

任务记录只在需求、里程碑和证据变化时更新。已有上下文提供的项目 revision 可直接用于一次写入，冲突或缺少信息时才重新读取，减少机械式查询和记录。

## 2026-11-16 验证

相同 GPT-6-Astra、xhigh、相同提示、相同四条链表记录，工具逐次返回下一条记录。旧版先跑，新版后跑，各一次，均返回 `[17, 53, 29, 91]`。

- 旧适配器：61.127 秒，五个推理步骤分别使用临时线程。
- 新适配器：19.662 秒，五个步骤复用同一线程与 turn；后续三次工具请求约 2.86、2.32、2.21 秒。
- 本次总耗时下降约 68%，约为原来的 1/3。服务负载、缓存和运行顺序未控制，样本只有一组；不能据此推断所有项目提速，也未与 Codex 桌面应用直接对照。

在独立插件仓库中，可用本机 Codex 登录执行 `node benchmarks/codex-continuity.mjs` 重跑这个小测试；它会实际调用模型。可用 `LINKMIND_BENCHMARK_MODEL` 指定本机目录中的其他模型。

额外使用真实 DSH 0.2.2-rc.2 隔离 profile 验证：四次文件读取始终使用同一 Codex 线程；运行中发送引导后停止遍历并输出要求的标记；自然语言创建 Goal、更新任务结论、结束 Goal 成功，数据库中只有一个对应任务；重启宿主后成功恢复同一线程并回复新消息。33 项 Python 回归和 22 项集成仓库 Node 回归通过。自动回归覆盖工具错误、图片、缺失结果、工作区隔离、线程恢复以及原生和斜杠 Goal 的绑定。

这是保留 DSH 工具和权限的 Codex 接入优化。工具集合、系统提示、审批、技能发现仍由 DSH 提供，体验不等同于直接运行完整 Codex。长历史首次导入、高推理等级和模型服务排队仍可能慢；外部控制方案的模型耗时也不由此适配器决定。
